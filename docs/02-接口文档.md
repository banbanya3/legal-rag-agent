# 接口文档

Base URL：`http://127.0.0.1:5000`（前端开发环境经 Vite 代理为 `/api`）

> **在线调试**：后端启动后访问 `http://127.0.0.1:5000/docs`，
> FastAPI 会自动生成可交互的 Swagger 文档，所有接口都能直接在页面上试。
> `http://127.0.0.1:5000/openapi.json` 是机器可读的 schema。

## 统一约定

### 响应结构

除 SSE 接口外，所有接口返回统一信封：

```json
{
  "code": 0,
  "message": "success",
  "data": { }
}
```

| 字段 | 说明 |
|---|---|
| `code` | `0` 成功；非 0 失败（`1` 业务错误、`400` 参数错误、`403` 权限、`404` 不存在、`500` 服务端异常） |
| `message` | 人类可读的提示，前端可直接弹 toast |
| `data` | 业务数据。列表接口为数组，对象接口为对象 |

### HTTP 状态码

业务错误统一用对应状态码返回，同时 body 仍是上面的结构：

| 场景 | HTTP | code |
|---|---|---|
| 成功 | 200 | 0 |
| 参数校验失败 | 400 | 400 |
| 非法操作 | 403 | 403 |
| 资源不存在 | 404 | 404 |
| 未捕获异常 | 500 | 500 |

### 前端封装

`src/api/http.js` 的响应拦截器已经把信封拆开，组件里拿到的就是 `data` 本身。

## 一、对话

### 1.1 流式对话（SSE）

```
POST /api/chat/stream
Content-Type: application/json
Accept: text/event-stream
```

**请求体**

```json
{
  "session_id": "s_abc123",
  "query": "试用期最长可以约定多久？",
  "use_rerank": true
}
```

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `session_id` | string | 是 | 前端生成的会话标识，后端不存在会自动建 |
| `query` | string | 是 | 用户问题，≤ 2000 字 |
| `use_rerank` | bool | 否 | 覆盖数据库里的精排开关；不传则用服务端配置 |

**响应**：`text/event-stream`，每一帧形如 `data: {...}\n\n`。

事件序列：

| 事件 type | 触发时机 | 关键字段 |
|---|---|---|
| `status` | 阶段变化 | `stage`（route/routed/retrieve/retrieved/generate）、`message`；`routed` 阶段额外带 `intent`、`domain`、`rewritten` |
| `sources` | 检索完成，生成之前 | `sources[]`，提前让前端展示"查到了哪些法条" |
| `delta` | 每个 token | `text` |
| `answer` | 生成结束 | `answer`、`sources`、`elapsed_ms`、`intent`、`domain` |
| `done` | 整轮结束 | `elapsed_ms` |
| `error` | 任意阶段异常 | `message` |

**完整示例**

```
data: {"type":"status","stage":"route","message":"正在理解你的问题…"}

data: {"type":"status","stage":"routed","message":"识别为法律咨询 · 检索范围：劳动与社会保障","intent":"advice","domain":"labor","rewritten":"试用期最长期限 劳动合同法第十九条"}

data: {"type":"status","stage":"retrieve","message":"正在检索劳动与社会保障相关条文…"}

data: {"type":"sources","sources":[{"title":"《劳动合同法》第十九条【试用期期限】","text":"劳动合同期限三个月以上不满一年的，试用期不得超过一个月……","score":0.9312,"law_name":"中华人民共和国劳动合同法","article_no":"第十九条","domain":"labor","domain_label":"劳动与社会保障","kind":"article","reranked":true,"source":"vector"}]}

data: {"type":"status","stage":"generate","message":"正在组织回答…"}

data: {"type":"delta","text":"试用期最长期"}

data: {"type":"delta","text":"限是六个月，但要看合同期限……"}

data: {"type":"answer","answer":"试用期最长期限是六个月……","sources":[...],"elapsed_ms":4213,"intent":"advice","domain":"labor","rewritten":"..."}

data: {"type":"done","elapsed_ms":4213}
```

> **客户端断开**：用户点"停止生成"会中断 HTTP 连接，服务端捕获 `GeneratorExit`，
> 把已生成的部分落库并追加"（已停止生成）"，不会丢这一轮对话。

### 1.2 非流式对话

```
POST /api/chat
```

请求体同上。响应：

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "session_id": "s_abc123",
    "answer": "试用期最长期限是六个月……",
    "sources": [ /* 同 SSE 的 sources */ ],
    "elapsed_ms": 4213
  }
}
```

> 内部复用 `stream_answer` 的事件流把 delta 拼起来，保证流式与非流式走同一套逻辑。

## 二、会话

### 2.1 会话列表

```
GET /api/sessions?keyword=试用期&limit=200
```

| 参数 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `keyword` | string | 空 | 按标题模糊搜索 |
| `limit` | int | 200 | 上限 500 |

```json
{
  "code": 0,
  "data": [
    {
      "session_id": "s_abc123",
      "title": "试用期可以约定多久",
      "created_at": "2026-10-28 16:20",
      "last_message_at": "2026-10-28 16:24",
      "message_count": 4
    }
  ]
}
```

> 排序按「最后一条消息时间」倒序；`message_count` 由一次 `GROUP BY` 算出，避免 N+1 查询。

### 2.2 会话消息

```
GET /api/sessions/{session_id}/messages
```

```json
{
  "code": 0,
  "data": [
    {
      "id": 12,
      "role": "user",
      "content": "试用期最长多久？",
      "sources": [],
      "elapsed_ms": 0,
      "created_at": "16:20"
    },
    {
      "id": 13,
      "role": "assistant",
      "content": "试用期最长为六个月……",
      "sources": [ /* 法条出处，历史回看也能展开 */ ],
      "elapsed_ms": 4213,
      "created_at": "16:20"
    }
  ]
}
```

### 2.3 新建会话（可选）

```
POST /api/sessions
```

```json
{ "code": 0, "data": { "session_id": "s_9f2c...", "title": "新对话" } }
```

> 正常流程不需要调这个：前端首次发消息时会自己生成 `session_id`，后端 `prepare_session` 自动落库。

### 2.4 重命名

```
PATCH /api/sessions/{session_id}
Content-Type: application/json

{ "title": "劳动合同试用期咨询" }
```

### 2.5 清空消息（保留会话）

```
DELETE /api/sessions/{session_id}/messages
```

```json
{ "code": 0, "message": "已清空 6 条消息", "data": { "deleted": 6 } }
```

### 2.6 删除会话

```
DELETE /api/sessions/{session_id}
```

先删子表 `chat_message` 再删主表 `chat_session`，避免外键冲突。

## 三、法条检索

### 3.1 分页检索

```
GET /api/statutes?keyword=试用期&domain=labor&law_name=劳动合同法&page=1&page_size=20
```

| 参数 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `keyword` | string | 空 | 同时匹配条文正文与条目标题 |
| `law_name` | string | 空 | 法律名模糊匹配 |
| `domain` | string | 空 | 六个领域 key 之一 |
| `page` | int | 1 | 页码 |
| `page_size` | int | 20 | 1—100 |

```json
{
  "code": 0,
  "data": {
    "total": 7,
    "page": 1,
    "page_size": 20,
    "items": [
      {
        "id": 218,
        "law_name": "中华人民共和国劳动合同法",
        "law_short": "劳动合同法",
        "domain": "labor",
        "domain_label": "劳动与社会保障",
        "chapter": "二、试用期",
        "article_no": "第十九条",
        "heading": "试用期期限",
        "content": "劳动合同期限三个月以上不满一年的，试用期不得超过一个月……",
        "effective_date": "2008-01-01",
        "source_file": "01_劳动合同法.md"
      }
    ]
  }
}
```

### 3.4 语义检索（供 MCP 调用）

```
GET /api/statutes/semantic?query=老板不给加班费&domain=labor&top_k=5
```

| 参数 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `query` | string | 必填 | 自然语言查询，1—200 字 |
| `domain` | string | 空 | 限定领域，空为全库 |
| `top_k` | int | 6 | 返回条数，1—12 |
| `use_rerank` | bool | true | 是否开启精排 |

```json
{
  "code": 0,
  "data": {
    "query": "老板不给加班费",
    "domain": "labor",
    "total": 4,
    "items": [
      {
        "title": "《劳动法》第四十四条【加班工资标准】",
        "text": "有下列情形之一的，用人单位应当按照下列标准支付……",
        "score": 0.627,
        "law_name": "中华人民共和国劳动法",
        "article_no": "第四十四条",
        "domain": "labor",
        "domain_label": "劳动与社会保障",
        "kind": "article",
        "reranked": true,
        "source": "vector"
      }
    ]
  }
}
```

**和 `GET /api/statutes` 的区别**：

- 那个走 MySQL `LIKE` 关键词匹配，只认字面，但精确、快（毫秒级）
- 这个把问题转成向量走向量库，能处理口语（"加班费" → "延长工作时间"），耗时 1—3 秒

这个接口主要供 MCP 服务调用 —— MCP 是独立进程，自己开 Milvus 会和主服务抢库锁。

### 3.5 精确取某一条

```
GET /api/statutes/劳动合同法/第十九条
```

`law_name` 支持模糊（传简称即可）。找不到返回 404。

### 4.1 领域概览

```
GET /api/knowledge/domains
```

```json
{
  "code": 0,
  "data": [
    {

      "desc": "劳动法、劳动合同法、工伤认定、社保缴纳、加班工资、劳动争议仲裁",
      "color": "#0f9d76",
      "dir": "02_labor",
      "collections": "law_labor",
      "vectors": 122,
      "docs": 5,
      "chunks": 122,
      "articles": 63,
      "chars": 48210,
      "files": [
        { "filename": "01_劳动合同法.md", "size_kb": 12.4 }
      ]
    }
  ]
}
```

### 4.2 上传文档

```
POST /api/knowledge/upload
Content-Type: multipart/form-data

file=@我的劳动合同.md
```

```json
{
  "code": 0,
  "message": "已上传 我的劳动合同.md，切分为 9 条可检索片段",
  "data": { "filename": "我的劳动合同.md", "chunks": 9, "chars": 5120 }
}
```

限制：`.txt` / `.md` / `.markdown`，单文件 ≤ 10 MB。
上传后立即切分进 `law_upload` 集合，和内置法律库物理隔离。

### 4.3 上传文档列表

```
GET /api/knowledge/documents
```

```json
{
  "code": 0,
  "data": [
    { "filename": "我的劳动合同.md", "size_kb": 5.0, "modified_at": "2026-10-28 16:30" }
  ]
}
```

### 4.4 删除上传文档

```
DELETE /api/knowledge/documents/{filename}
```

只允许删 `storage/uploads/` 下的文件，内置知识库文件不可从此接口删除。

### 4.5 重建索引

```
POST /api/knowledge/rebuild
Content-Type: application/json

{ "domain": "labor", "force": true }
```

| 字段 | 说明 |
|---|---|
| `domain` | 省略或 `null` 表示全量 |
| `force` | `true` 先删集合再重建；`false` 走内容指纹增量（文件没改就跳过） |

```json
{
  "code": 0,
  "message": "索引构建完成：1 个领域 / 122 条切片 / 63 条法条",
  "data": {
    "domains": [
      { "domain": "labor", "label": "劳动与社会保障", "files": 5, "chunks": 122, "articles": 63, "failed": [] }
    ],
    "total_chunks": 122,
    "total_articles": 63
  }
}
```

> 耗时较长（涉及 embedding 接口），前端超时设为 600 秒。

## 五、系统设置

### 5.1 读取设置

```
GET /api/settings
```

```json
{
  "code": 0,
  "data": {
    "provider": "zhipu",
    "model_name": "glm-4-flash",
    "api_key_masked": "c30bbq********h7k2",
    "has_api_key": true,
    "base_url": "https://open.bigmodel.cn/api/paas/v4/",
    "temperature": 0.1,
    "top_k": 8,
    "rerank_n": 4,
    "use_rerank": true,
    "strict_mode": true,
    "updated_at": "2026-10-28 16:00"
  }
}
```

密钥永远脱敏返回，浏览器拿不到明文。

### 5.2 保存设置

```
POST /api/settings
Content-Type: application/json

{
  "provider": "zhipu",
  "model_name": "glm-4-flash",
  "api_key": "",
  "base_url": "https://open.bigmodel.cn/api/paas/v4/",
  "temperature": 0.1,
  "top_k": 8,
  "rerank_n": 4,
  "use_rerank": true,
  "strict_mode": true
}
```

`api_key` 留空表示沿用已保存的，避免"打开设置直接保存"把 Key 清空。

校验：`temperature` 0—1.5、`top_k` 1—30、`rerank_n` 1—10，越界返回 400。

### 5.3 测试连通性

```
POST /api/settings/test

{ "model_name": "glm-4-flash", "base_url": "https://open.bigmodel.cn/api/paas/v4/", "api_key": "" }
```

```json
{
  "code": 0,
  "data": {
    "success": true,
    "message": "连接成功，模型已正常响应",
    "latency_ms": 862,
    "model_reply": "收到"
  }
}
```

真实发一次请求，把 HTTP 状态码和原始报错原样带回，便于定位
"Key 无效 / 模型名不存在 / Base URL 写错"。

### 5.4 模型预设

```
GET /api/models
```

返回四组预设（智谱 / DeepSeek / 通义 / 自定义），前端下拉框直接渲染。

## 七、错误响应示例

```json
{ "code": 400, "message": "问题不能为空", "data": null }
```

```json
{ "code": 404, "message": "未收录：劳动合同法 第九十九条", "data": null }
```

```json
{ "code": 500, "message": "服务器内部错误：OperationalError: (2003, \"Can't connect to MySQL server\")", "data": null }
```

`500` 只把异常类型和简述返回给前端，完整堆栈打在服务端日志里，不泄露内部细节。
